SETTINGS SYNC COMPATIBILITY CONTRACT

UDP 45439, authenticated AES-GCM, existing key derivation and AAD remain stable.
Version 1 is the additive wire envelope; advertise optional features through
Capabilities rather than incrementing Version for a new field. Send a v2 bridge
view for the already-released v0.4.0 reader. Local storage can remain version 2.
Replies use the requester's envelope version. No secrets or power commands sync.

TV JSON round-trips unknown device fields. Discovery preserves them. A legacy
edit that omits them must not erase locally known settings. Explicit JSON null
can represent a future field's intentional clearing. New global settings need
equivalent preservation before introduction; do not assume this device-field
mechanism covers new top-level collections.

Disabled is capability-gated and independently revisioned. Future features must
use equivalent independent revisions/presence semantics, and be excluded from
common-field equality when appropriate. Absent features mean unsupported, not
reset-to-default. Readers must ignore unsupported optional features rather than
rejecting the whole compatible packet. New device kinds require a legacy-view
filter/negotiation because old readers reject unknown Kind values; adding one
unfiltered to the legacy broadcast would break their common-settings sync.

Frozen v0.3.0 and v0.4.0 receiver fixtures are in sync_compat_test.go. Extend them
for every wire-facing feature; retain old wire/encryption behavior. The v0.4.0
bridge uses a transport-only one-nanosecond record priority so its whole-record
merge accepts the feature view regardless of packet order. Updated readers
normalize that priority, and ignore unchanged legacy echoes so it cannot
accumulate. Do not use the bridge priority as a permanent logical revision.

Old applications cannot honor behavior they did not implement. Compatible
settings exchange does not make Disabled work on pre-0.4 installations.

Packet freshness (v0.4.3): outgoing packets include optional SentAt (Unix
nanoseconds) inside the authenticated JSON. It is not a device revision and
is never stored in local snapshots. Updated receivers accept it within five
minutes of their clock; zero/absent remains compatible with old senders.
The LAN receive loop suppresses exact duplicate authenticated datagrams before
merge or reply using a bounded 4096-entry, ten-minute in-memory cache. The
cache resets on restart and may evict entries at capacity. Old unstamped
captures cannot be given complete expiry without breaking their wire format.
AES-GCM, key derivation, AAD, port, and v0.4.0 bridge behavior remain unchanged.
